# 9. Bitfocus Companion (Stream Deck)

Control the MCS-8M from Stream Deck buttons with [Bitfocus Companion](https://bitfocus.io/companion). There's no dedicated MCS-8M module, but two of Companion's built-in generic modules do the job:

| Module | Job |
|---|---|
| **Generic: TCP Serial** | Opens the serial port on the Companion computer and makes it available as a local TCP port (32100 by default). It has no actions of its own. |
| **Generic: TCP/UDP** | Connects to that TCP port. Its action **Send HEX encoded Command** sends the raw bytes of one MCS-8M frame. |

```
Stream Deck ─► Companion ─► Generic TCP/UDP ─► 127.0.0.1:32100 ─► Generic TCP Serial ─► USB-RS232 ─► MCS-8M
```

✅ **What's been checked:**
- **The hex action's behaviour:** read from the module's source code (generic-tcp-udp v2.3.0).
- **The command frames:** generated by [`tools/companion_commands.py`](../tools/companion_commands.py). They match Sony's own examples and frames captured from a real unit.
- **The network bridge:** the ser2net setup below was tested against the [simulator](../tools/simulator.py).

❓ **Not yet tested:** a full Stream Deck → Companion → real switcher run. If you try it, please report back in an issue.

## Before you start

- Serial control enabled on the switcher, **Serial Cmd Group = Rem 1** ([Hardware](07-hardware.md#required-enable-serial-control-on-the-switcher)).
- The serial adapter and null-modem cable working. The [loopback test](07-hardware.md#1-the-adapter-loopback-test) checks this.
- **Only one program can open the serial port.** Stop Node-RED or anything else that uses it, or see [Sharing with Node-RED](#sharing-the-switcher-with-node-red).

## Setup A: Companion on the computer plugged into the switcher

1. In Companion's **Connections** tab, add **Generic: TCP Serial**:
   - **Serial Port:** your adapter, e.g. `COM3` or `/dev/ttyUSB0`
   - **Baud Rate** `38400`, **Data Bits** `8`, **Parity** `None`, **Stop Bits** `1`
   - **Listen Port:** `32100` (the default)
2. Add **Generic: TCP/UDP**, and name it e.g. `mcs8m`:
   - **Target IP** `127.0.0.1`, **Target Port** `32100`, protocol **TCP**
3. Both connections should show green (OK).

## Setup B: Companion on a different computer

Put a small bridge next to the switcher, then point **Generic: TCP/UDP** at that machine's IP address and port. Setup A's TCP Serial module isn't needed in this case.

**With a Raspberry Pi and ser2net** (✅ tested against the simulator):

```sh
sudo apt-get install -y ser2net
sudo nano /etc/ser2net.yaml      # replace the contents with the block below
sudo systemctl restart ser2net
```

```yaml
connection: &mcs8m
    accepter: tcp,32100
    enable: on
    options:
      kickolduser: true
    connector: serialdev,/dev/ttyUSB0,38400n81,local
```

Use `tcp` (raw), **not** `telnet`: telnet mode changes some byte values. Leave out the `banner:` option that the default file uses. For a name that never changes, use the `/dev/serial/by-id/…` path instead of `/dev/ttyUSB0`.

**A hardware serial-to-Ethernet adapter** (a "serial device server") also works. Set it to 38400 8N1, no flow control, **raw TCP server** mode. This is untested here.

## Making a button

1. Create a button and add the action **mcs8m: Send HEX encoded Command**.
2. **Command:** paste a hex string from the table below, **exactly as shown**.
3. **Command End Character:** **None**. This is the default for the hex action.
4. Press the button. The switcher acts on it within a few milliseconds. Its reply comes back about 1 s later for video commands, and you don't need to wait for it.

### ⚠️ Three rules

| Rule | Why |
|---|---|
| **No spaces** in the hex | The module stops decoding at the first space. `01 02 00 09 …` would send just the single byte `01`. |
| **End Character = None** | The MCS-8M drops any frame with extra bytes, such as `\r\n`, attached. |
| **One frame per action** | For several commands on one button, add several actions. Space them ~100 ms apart using Companion's action delays. ❓ Commands sent back-to-back may also work, but that hasn't been tested. |

## Button feedback (tally on the Stream Deck)

The generic module **can't reliably light buttons** to show what's live. It only keeps the *last* thing received, in `$(mcs8m:tcp_response)` (turn on *Save TCP Response* and set it to *Hex*). The switcher sends many kinds of frames, and they can arrive split or merged, so that variable often doesn't hold the one you want.

Proper feedback needs a dedicated Companion module that frames replies by byte count. That's what [`examples/javascript/mcs8m.js`](../examples/javascript/mcs8m.js) does, so it's a good starting point. Until someone builds one, use Companion for **actions**, and the [Node-RED dashboard](../examples/node-red/dashboard/) or the [tally example](../examples/python/03_tally.py) to **see** what's live.

## Sharing the switcher with Node-RED

The serial port can only be opened by one program at a time. To use the dashboard **and** Companion together, let **ser2net** (Setup B) own the port. Then connect both to it over TCP:
- Companion uses Generic TCP/UDP, as above;
- in Node-RED, replace the serial-in and serial-out nodes with a TCP-in and a TCP-out node set to *connect to* the ser2net port, with output as a *stream of Buffers*. The dashboard's parser works unchanged, because it frames by byte count.

❓ This hasn't been tested. ser2net normally allows only one client per port, so you'd need a ser2net version or setup that allows several. The Generic: TCP Serial module allows up to 4, so Companion's computer can host the port for Node-RED instead.

## Troubleshooting

| Symptom | Check |
|---|---|
| Nothing happens | The TCP/UDP connection is green; **End Character = None**; no spaces in the hex; Rem 1 is set on the switcher. |
| TCP Serial connection is red | The port is in use by another program (e.g. Node-RED), or it's the wrong port name. |
| Works from Python but not from Companion | Compare Companion's debug log (it logs the hex it sends) with the table. Most likely a space or line ending crept in. |
